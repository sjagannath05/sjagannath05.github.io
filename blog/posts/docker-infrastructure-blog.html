Eight files, forty-four lines, five of them metadata

The DNS image for our private PGWs is two lines of Dockerfile; the rest of the repository says where that image goes and who owns it.

What the first commit added

The initial commit (16 July 2024) created eight files totalling 44 lines. Two of those lines are the image itself (FROM and EXPOSE, nothing else). Five of the files are metadata — naming, ownership, promotion rules. That is the right proportion for a service whose job is to be upstream CoreDNS at a known tag.

There is no Corefile in it. Configuration is mounted at deploy time, so nothing committed here changes the answer to a query. It changes which binary answers — and which registry that binary came from.

The service name is spelled once

SERVICE_NAME := $(shell cat meta-dev.yml | grep service: -m1 | cut -d ':' -f2 | xargs)
VERSION := red
IMAGE := registry.internal/jenkins/$(SERVICE_NAME):${VERSION}

The Makefile reads the name back out of meta-dev.yml. It takes the first match (grep -m1) and trims the whitespace with xargs. A crude parse, with no yq and no YAML library, and it does the one thing worth doing. A rename lands in a single file and the image path follows it.

The tag is the development tag red. The Actions workflow names that tag too (image_additional_tags: red), so it is the one string this repository spells twice.

test: echo "no tests"

test:
        echo "no tests"

That target arrived in the first commit and has never been filled in. A unit test for a pinned base image would assert that the base image is the base image. It would fail only when the upstream registry does.

The promotion gate stands in for it. promote_to_dev fires on main or any deploy-dev/* branch (mode: always), and promote_to_prod moves the artefact that already passed. The image is promoted, not rebuilt — which matters, because a rebuild of the same Dockerfile produces a different digest.

The rest is a contract

The remainder of meta-dev.yml is who to wake and what not to look for. A squad, a primary and a secondary maintainer (two names, no rota), and public_api: false alongside private_api: false so the platform stops hunting for an API spec.

VERSION holds 1.11.1, which is the upstream release and not a number of our own. There is nothing to keep in step; CHANGELOG.md has exactly one line in it.

Nineteen months passed between the first commit and the second (16 July 2024 to 11 February 2026). For a repository that pins a base image and names its owners, that silence is the design working. The CI migration eventually forced a change, and it had nothing to do with DNS.
